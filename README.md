# SQL Bootcamp

## О проекте

**SQL Bootcamp** — практический учебный проект по работе с **реляционными базами данных и PostgreSQL**.

Обучение было построено как последовательность индивидуальных заданий и командных проектов. Задания постепенно переходили от базовых конструкций SQL и работы с реляционной моделью к более сложным операциям с данными, индексам, транзакциям, OLAP-конструкциям и работе с Data Warehouse.

Основная цель проекта — получить практический опыт работы с базами данных и научиться решать задачи с использованием SQL.

---

## Формат обучения

Bootcamp состоял из двух частей:

* **индивидуальные задания** — последовательное изучение SQL и возможностей реляционных баз данных;
* **командные проекты** — применение полученных знаний для решения более комплексных задач.

В качестве СУБД использовался **PostgreSQL**.

# Индивидуальные задания

## Day 00 — Реляционная модель данных и SQL

Первый день был посвящён основам реляционной модели данных и базовым конструкциям SQL.

В рамках задания изучалась работа с реляционными данными и получение необходимой информации с помощью SQL-запросов.

**Основная тема:**

* реляционная модель данных;
* базовые конструкции SQL;
* получение данных из базы.

---

## Day 01 — Множества и JOIN

На этом этапе началась работа с множествами и объединением данных из нескольких таблиц.

Изучались базовые конструкции `JOIN` и способы получения необходимой информации на основе связанных наборов данных.

**Основная тема:**

* множества;
* `JOIN`;
* работа со связанными данными.

---

## Day 02 — Работа с различными JOIN

Задание было посвящено более глубокому изучению `JOIN`.

Рассматривались различные структуры объединения таблиц и способы их использования для получения данных.

**Основная тема:**

* различные структуры `JOIN`;
* объединение данных из таблиц;
* построение SQL-запросов с использованием `JOIN`.

---

## Day 03 — JOIN и изменение данных

На этом этапе работа с `JOIN` продолжилась, а также появилась работа с изменением данных.

Изучался **DML (Data Manipulation Language)** и операции, позволяющие изменять данные в базе.

**Основная тема:**

* `JOIN`;
* DML;
* изменение данных.

---

## Day 04 — VIEW и Snapshots

Задание было посвящено двум способам работы с представлением данных:

* **VIEW** — виртуальное представление данных;
* **snapshot** — сохранённое состояние данных.

Изучалось, как использовать представления и snapshots при работе с базой данных.

**Основная тема:**

* `VIEW`;
* snapshots;
* работа с представлением данных.

---

## Day 05 — Индексы

Следующий этап был посвящён индексам и их использованию при работе с базой данных.

В рамках задания изучалось, **как и когда создавать индексы**, чтобы улучшать работу с запросами.

**Основная тема:**

* индексы;
* создание индексов;
* применение индексов.

---

## Day 06 — Изменение модели данных

На этом этапе необходимо было добавить новую бизнес-функциональность в существующую модель данных.

Задание было направлено на понимание того, как изменения бизнес-логики могут отражаться на структуре и данных базы.

**Основная тема:**

* модель данных;
* добавление новой бизнес-функции;
* изменение существующей структуры данных.

---

## Day 07 — Агрегированные данные и OLAP

Задание было посвящено работе с агрегированными данными.

Изучались специальные **OLAP-конструкции**, которые позволяют получать дополнительную аналитическую информацию из набора данных.

**Основная тема:**

* агрегированные данные;
* OLAP-конструкции;
* получение аналитических значений из данных.

---

## Day 08 — Транзакции и уровни изоляции

На этом этапе изучалась работа базы данных с транзакциями.

Отдельное внимание уделялось **уровням изоляции транзакций** и тому, как база данных обеспечивает корректную работу с параллельными операциями.

Также рассматривалась связь транзакций со свойствами **ACID**.

**Основная тема:**

* транзакции;
* уровни изоляции;
* ACID.

---

## Day 09 — Функциональные блоки базы данных

Заключительное индивидуальное задание было посвящено созданию и использованию функциональных блоков внутри базы данных.

**Основная тема:**

* функциональные блоки базы данных;
* создание функциональных блоков;
* использование функциональных блоков.

# Командные проекты

## Team 00 — Traveling Salesman Problem

Командный проект, посвящённый **задаче коммивояжёра (Traveling Salesman Problem)**.

Цель проекта — реализовать решение задачи средствами SQL и получить необходимый результат с использованием базы данных.

Проект выполнялся в команде и позволил применить знания SQL для решения отдельной алгоритмической задачи.

**Использовались:**

* PostgreSQL;
* SQL;
* работа с данными;
* командная работа.

---

## Team 01 — Data Warehouse

Командный проект, посвящённый **Data Warehouse (DWH)**.

В рамках проекта изучалось, что такое хранилище данных, а также создавался первый **ETL-процесс**.

**DWH (Data Warehouse)** — хранилище данных, предназначенное для централизованного хранения данных, которые могут использоваться для аналитических задач.

**ETL** — процесс работы с данными, состоящий из трёх этапов:

1. **Extract** — получение данных;
2. **Transform** — преобразование данных;
3. **Load** — загрузка данных.

Таким образом, в рамках командного проекта мы познакомились с основами построения процесса загрузки данных в хранилище.

**Использовались:**

* PostgreSQL;
* SQL;
* Data Warehouse;
* ETL;
* командная работа.
